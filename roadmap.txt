RADIO & TV STORY SEGMENTER - DEVELOPMENT ROADMAP & TECHNICAL SPECIFICATION
================================================================================
This document outlines the architectural roadmap and implementation specifications
for future versions of the Radio & TV Story Segmenter. Adapted from best-in-class
heuristics, modular runtime architectures, and timeline serialization algorithms.
--------------------------------------------------------------------------------
ROADMAP MAINTENANCE POLICY: N-1 SLIDING-WINDOW & STATUS TRACKING
--------------------------------------------------------------------------------
- The roadmap maintains a rolling window: it displays the current/immediate past
  release ($N-1$) for baseline context, followed by active upcoming development
  milestones ($N$, $N+1$).
- Status Notation Policy (Modeled after Social Digest):
  * All milestones and feature items are annotated with explicit progress indicators:
    - [x] Completed item / feature
    - [-] In-progress item / active development
    - [ ] Planned / not started item
  * When work commences on an item, mark it immediately as [-] [IN-PROGRESS].
  * Mark an item as [x] [COMPLETED] when implementation is finalized, upon user
    confirmation, or inferred when development transitions to another part of the roadmap.
- ARCHITECTURAL DETAILS & CROSS-REFERENCE DIRECTORY:
  * To maintain strict file-budget hygiene and avoid token bloat, comprehensive code-level
    audits, call stacks, repro evidence, and diffs are preserved in dedicated technical documents:
    - Code Audit Findings & Bug Fixes: `docs/audit/audit_phase1_findings.md` through `audit_phase7_findings.md`
    - Master Audit Plan & Prioritization: `docs/audit/audit_roadmap.md`
    - Subsystem Architecture & IPC Specifications: `ARCHITECTURE.md`
    - Release Logs & Historical Commits: `CHANGELOG.md`
- "WHAT'S NEXT" PROTOCOL FOR AI STUDIO:
  * Whenever the user asks "what's next" (or asks for an update on the roadmap), DO NOT immediately modify code or take action.
  * State what is next on the roadmap, outline the issue or feature, and suggest possible next steps.
  * STOP and wait for the user to confirm whether they would like to proceed before making any changes.
  * When implementing confirmed tasks:
    - NEVER combine multiple sub-items in a single response unless requested.
    - NEVER truncate any file with placeholders (`# ... existing code ...`).
    - ALWAYS preserve 100% backward compatibility by re-exporting all extracted classes,
      functions, and constants in the original facade module and `prs_shared.py`.
    - ALWAYS keep every new or modified `.py` file under the 1,000-line ceiling (~800 lines target).

1. IMMEDIATE PREDECESSOR RELEASE: WORDPRESS EPISODE BACKFILL, UPDATE EXISTING POST MODE & PUBLICATION DATE SCHEDULING:
- Purpose: Enable updating older WordPress episode pages in-place with full transcripts and segmented story pages without breaking existing URLs, unpublishing live posts, altering Seriously Simple Podcasting (Castos) RSS enclosures/GUIDs, or losing original show-notes excerpts, while also supporting custom publication date scheduling for both new and updated episodes.
- Target Release: v3.9.96-beta (Immediate Predecessor Release)
- Technical References & Implementation Details:
  * [x] Dedicated Backfill Submodule (`plugins/wordpress/episode_updater.py`): Added URL/slug/ID parser (`extract_slug_or_id_from_url`), HTML-to-excerpt extractor (`clean_html_to_plain_excerpt`), slug builder (`build_story_slug`), ISO-8601 date normalizer (`normalize_wp_iso_date`), REST post resolver (`resolve_wp_post_from_url`), remote MP3 downloader (`download_wp_episode_audio`), two-mode UI controls (`setup_wp_mode_and_date_ui`), and `LoadWordPressEpisodeDialog`.
  * [x] REST Client & Upload Engine (`plugins/wordpress/client.py`): Extended `create_post()`, `update_post()`, and `execute_wordpress_upload()` with `date`, `slug`, `existing_post_id`, `replace_existing_audio_and_podcast`, and `post_status`, skipping full-episode MP3 uploads and Castos meta/series overwrites when preserving existing episode audio.
  * [x] Export Destination & Tab Integration (`plugins/wordpress/export_destination.py`, `wp_ui_builder.py`, `wp_tab_widget.py`, `wp_post_builder.py`, `plugin.py`): Added auto-resolution on export, Option B body-to-excerpt promotion with `_autofill_all_excerpts` protection, clean permalink slug links in the Full Episode Table of Contents, `Apply to all stories (excludes Full Episode)` Story category sync, dynamic `sync_wp_audio_checkbox_label()` wording, and `File > Open Existing WordPress Episode...` / export menu actions via `BasePlugin.get_file_open_actions()` (`plugin_base.py`, `ui_menus.py`).
  * [x] User Guide Documentation (`docs/guides/getting_started_and_workflow.md`, `docs/guides/wordpress_exporting.md`, `embedded_guides.py`): Documented `File > Open Existing WordPress Episode...`, the two Workflow Modes, shared Publication Date field, post status dropdowns, Option B excerpt preservation, and Castos MP3/RSS feed protection across both Markdown guides and embedded fallbacks.
  * [x] Automated Diagnostic Coverage (`diagnostic_export_tests.py`): Verified URL parsing, Option B excerpt preservation, date backdating, Full Episode in-place updates, Story draft audio uploads, and clean TOC slug links.
