This document outlines the architectural roadmap and implementation specifications
for future versions of the Radio & TV Story Segmenter. Adapted from best-in-class
heuristics, modular runtime architectures, and timeline serialization algorithms.

--------------------------------------------------------------------------------
ROADMAP MAINTENANCE POLICY: N-1 SLIDING-WINDOW & STATUS TRACKING
--------------------------------------------------------------------------------
- The roadmap maintains a rolling window: it displays the current/immediate past
  release ($N-1$) for baseline context, followed by active upcoming development
  milestones ($N$, $N+1$).
- Status Notation Policy (Modeled after Social Digest):
  * All milestones and feature items are annotated with explicit progress indicators:
    - [x] Completed item / feature
    - [-] In-progress item / active development
    - [ ] Planned / not started item
  * When work commences on an item, mark it immediately as [-] [IN-PROGRESS].
  * Mark an item as [x] [COMPLETED] when implementation is finalized, upon user
    confirmation, or inferred when development transitions to another part of the roadmap.
- When a new version is built, its completed specifications are recorded, and any
  versions older than $N-1$ are pruned to keep the document focused and actionable.
- Whenever any code change, bug fix, packaging adjustment, or feature refinement is
  made during a release cycle, it MUST be recorded immediately in the current release
  section of roadmap.txt and CHANGELOG.md (even if it occurs after the initial version
  number bump).

1. PREVIOUS RELEASE: WINDOWS UNINSTALLER DATA CLEANUP & IN-APP STORAGE MANAGER (Completed in v3.2.3)
================================================================================

[x] 1.1 INTERACTIVE INNO SETUP UNINSTALL PROMPT
------------------------------------------------
- Added custom Inno Setup `[Code]` uninstall procedure `CurUninstallStepChanged` to `installer/Windows/RadioTVStorySegmenter.iss`.
- Prompts user during Windows uninstallation: "Would you like to also remove saved preferences, log files, and downloaded AI models?".
- Safely deletes `%LOCALAPPDATA%\RadioTVStorySegmenter` and registry keys when 'Yes' is chosen while protecting exported media and project files.

[x] 1.2 CROSS-PLATFORM IN-APP STORAGE & MODEL PURGE MANAGER
------------------------------------------------------------
- Implemented `purge_all_data()` in `model_management.py` and exposed "Purge All Models & Cache Data…" button in the Preferences dialog and Model Manager.
- Enables macOS, Linux, and Windows users to delete downloaded Whisper ASR models, translation models, diagnostic logs, and temporary caches in one click to reclaim multi-gigabyte disk space at any time.

================================================================================
2. CURRENT RELEASE: CPU-FIRST DIARIZATION & TRANSLATION, CUDA PRUNING & INSTALLER CACHE (Completed in v3.2.4)
================================================================================

[x] 2.1 TRANSLATION & DIARIZATION RUNTIME CUDA REMOVAL
------------------------------------------------------
- Stripped all unused CUDA/cuDNN dependencies from both the isolated translation (`runtimes/translate`) and diarization (`runtimes/diarize`) environments.
- Enforced PyTorch CPU wheel index (`https://download.pytorch.org/whl/cpu`) in `ENV_CONFIGS`, reducing environment footprints by over 1.4 GB per environment.
- Preserved 100% INT8 translation performance using CPU-optimized CTranslate2 execution and fast ONNX WeSpeaker diarization.
- Bumped isolated translate environment version to `2.9` and diarize environment version to `1.1.0`.

[x] 2.2 AUTOMATED RUNTIME CUDA PRUNING
--------------------------------------
- Added `RuntimeManager.prune_cuda_artifacts(env_dir)` to systematically delete heavy NVIDIA directories (`**/nvidia`) and loose CUDA libraries (`libnvrtc*`, `libcudnn*`, `libcublas*`, `torch_cuda*`, etc.).
- Integrated automated pruning across `translate` and `diarize` runtimes in `RuntimeManager.ensure_environment` and `model_management.py` upon inspection and post-install.

[x] 2.3 APPDATA INSTALLER CACHE MANAGEMENT & AUTOMATIC CLEANUP
-------------------------------------------------------------
- Implemented `cleanup_old_installers(max_to_keep=1, force_all=False)` in `updater.py` to scan `AppData/updates` (and macOS/Linux app data directories) and delete outdated installer binaries (`.exe`, `.dmg`, `.pkg`, `.deb`, `.rpm`, `.AppImage`, `.zip`, `.tar.gz`) and orphaned `.download` files.
- Hooked automated cleanup into app startup, background update checks, download completion, and the Check for Updates dialog.
- Added Downloaded Update Installers inspection, size tracking, and deletion to `model_management.py` and connected it to `purge_all_data()`.

[x] 2.4 DOCUMENTATION & BUILD SPECIFICATION SYNCHRONIZATION
-----------------------------------------------------------
- Synchronized `README.md`, `BUILD_INSTRUCTIONS.txt`, `STABILITY_NOTES.md`, and `ARCHITECTURE.md` to document CPU-first architecture for translation and diarization and clarify optional Whisper GPU acceleration.
