This document outlines the architectural roadmap and implementation specifications
for future versions of the Radio & TV Story Segmenter. Adapted from best-in-class
heuristics, modular runtime architectures, and timeline serialization algorithms.

--------------------------------------------------------------------------------
ROADMAP MAINTENANCE POLICY: N-1 SLIDING-WINDOW & STATUS TRACKING
--------------------------------------------------------------------------------
- The roadmap maintains a rolling window: it displays the current/immediate past
  release ($N-1$) for baseline context, followed by active upcoming development
  milestones ($N$, $N+1$).
- Status Notation Policy (Modeled after Social Digest):
  * All milestones and feature items are annotated with explicit progress indicators:
    - [x] Completed item / feature
    - [-] In-progress item / active development
    - [ ] Planned / not started item
  * When work commences on an item, mark it immediately as [-] [IN-PROGRESS].
  * Mark an item as [x] [COMPLETED] when implementation is finalized, upon user
    confirmation, or inferred when development transitions to another part of the roadmap.
- When a new version is built, its completed specifications are recorded, and any
  versions older than $N-1$ are pruned to keep the document focused and actionable.
- Whenever any code change, bug fix, packaging adjustment, or feature refinement is
  made during a release cycle, it MUST be recorded immediately in the current release
  section of roadmap.txt and CHANGELOG.md (even if it occurs after the initial version
  number bump).

CORE ARCHITECTURAL INVARIANTS
================================================================================
- Core modules must NEVER import from plugins/.
- Heavy translation runtimes must remain isolated inside plugins/translation/.
- Speaker diarization uses wespeakerruntime as the primary ONNX embedding engine.
- Real-time progress updates with percentage, status messages, and estimated time.
- Diagnostic logs written to OS standard logging locations.
- Offline-first architecture: core processing functions locally without internet.
- 0 MB Default GPU Footprint: Base installer contains 0 MB of CUDA bloat; GPU features are purely optional and provisioned on demand.

2. CURRENT RELEASE: AUDIO FADES "APPLY" & TIMELINE NAVIGATION OPTIMIZATION (Completed in v3.5.8)
================================================================================

[x] 2.1 AUDIO FADES DIALOG "APPLY" ACTION & LIVE AUDITIONING (transcript_story.py)
-----------------------------------------------------------------------------------
- Added an "Apply" button in `StoryFadesDialog` alongside "Save Fades" and "Cancel", allowing real-time timeline visualization and playback auditioning without closing the dialog.
- Preserved a pre-dialog snapshot (`_initial_fades`) across all stories, ensuring clicking "Cancel" after applying reverts all modifications seamlessly.
- Aligned `MainWindow.edit_story_fades` undo/redo stack commands with the pre-dialog baseline values, guaranteeing predictable single-step undo history.

[x] 2.2 TIMELINE DRAG & SCRUB PERFORMANCE THROTTLING (timeline_widgets.py)
---------------------------------------------------------------------------
- Implemented a 60 FPS (~16ms) rate limiter in `TimelineCanvas.mouseMoveEvent` during dragging, scrubbing, fade handle adjustment, and region selection.
- Prevented UI thread event loop starvation and eliminate mouse lag during rapid pointer gestures.

[x] 2.3 DEFERRED SIDEBAR LIST RELAYOUT (transcript_story.py)
-------------------------------------------------------------
- Removed continuous `QListWidgetItem` string reformatting and serialization from `handle_drag_story_region`.
- Kept numerical start/end inputs responsive in real-time, deferring full sidebar item relayout to `handle_drag_finished`.

[x] 2.4 PRECOMPUTED FADE CURVE LOOKUP TABLES & VECTOR CACHING (timeline_widgets.py)
------------------------------------------------------------------------------------
- Precomputed 16-step lookup tables for all fade curve profiles (`linear`, `s_curve`, `logarithmic`, `exponential`), eliminating repeated exponential/trigonometric function evaluations per story per frame.
- Pre-cached QPen and QBrush objects in `TimelineCanvas` for fade fills, ramps, and grab handles.
- Cached story boundary snapping points in `set_stories` and during active drag updates.

[x] 2.4 UNIFIED EXPORT CENTER & MENU INTEGRATION
-------------------------------------------------
- Added REAPER and Samplitude checkboxes in `UnifiedExportDialog` with persistent `QSettings` support.
- Added dedicated "Export Timeline / DAW" submenu in File menu and integrated with batch export pipeline.

[x] 2.5 DIAGNOSTIC TEST BENCH EXPANSION (test_runner.py)
--------------------------------------------------------
- Added automated diagnostic tests verifying REAPER project syntax, Samplitude EDL structure, and chapter marker zero-start formatting.

[x] 2.6 CI/CD PIPELINE HARDENING & ARTIFACT STAGING (.github/workflows/build.yml)

- Isolated package staging in `dist/release_packages/` to bypass heavy unbundled PyInstaller build folders during artifact uploads.

3. ACTIVE FEATURE MILESTONE: WORDPRESS METADATA & WINDOW EXPANSION CONTROLS [PLANNED for v3.6.0]
================================================================================

[ ] 3.1 Story Editor WordPress Metadata Assignment
--------------------------------------------------
- Expose all WordPress export options (Author, Excerpt, Categories, Tags, Featured Image, Post Status/Schedule) within the main Stories widget/editor view.
- Allow users to assign and preview story-level WordPress post data directly while editing story boundaries and transcripts.

[ ] 3.2 Project File Serialization & Export Pre-Population
-----------------------------------------------------------
- Store assigned WordPress metadata inside the `.rtvs` project file structure (`stories` JSON records).
- Pre-populate these settings automatically into the `UnifiedExportDialog` WordPress tab during export, while retaining full editability at export time.

[ ] 3.3 Export Window Fullscreen Expansion Controls
----------------------------------------------------
- Add dedicated Maximize / Fullscreen and Restore / Minimize window controls to `UnifiedExportDialog`.
- Allows the export center to expand to true full screen for managing complex multi-story publishing tasks, with seamless toggle back to standard dialog dimensions.

[ ] 3.4 Story Widget Workspace Expansion Controls
--------------------------------------------------
- Add dedicated Maximize / Expand and Restore / Minimize buttons to the Story Editor widget in the main application window.
- Allows the story view to expand to fill the entire application window workspace for focused editing, and collapse back to its standard split layout once finished.

[ ] 3.5 Audio Fades Dialog "Apply" Action & Live Auditioning
-------------------------------------------------------------
- Add an explicit "Apply" button to `StoryFadesDialog` alongside "Save Fades" and "Cancel".
- Dispatches changes to the active story/project immediately so users can visually inspect fade shapes on the timeline and audition audio envelopes with real-time fade cues without closing the modal dialog.

[ ] 3.6 Timeline Navigation & Boundary Drag Performance Optimization
--------------------------------------------------------------------
- Event Throttling: Implement a high-resolution time gate (~16ms / 60 FPS) in `TimelineCanvas.mouseMoveEvent` to prevent flooding the Qt event loop during rapid mouse movements.
- Defer Intermediate List Item Layouts: In `handle_drag_story_region`, eliminate mid-drag `QListWidgetItem.setText` and item serialization calls; update only coordinate inputs (`start_input`, `end_input`) during drag and execute the full list item refresh only upon `mouseReleaseEvent`.
- Precomputed Fade Curve Caching: Cache calculated `QPainterPath` vectors for each story's fade envelopes rather than dynamically evaluating 16 curve steps across all visible stories on every paint event.
- Tooltip Debouncing: Suppress continuous `QToolTip.showText` repositioning calls while actively dragging handles or panning.

[ ] 3.7 Project Export & Lifecycle Modularization
-------------------------------------------------
- Extract project open, save, close, dirty flag tracking, and undo stack resets from `project_export.py` into a standalone `project_lifecycle.py`.
- Migrate audio rendering engines (broadcast WAV formatting, stem splitting, ID3v2 tag writing, MP3 encoding) into dedicated modules inside `export/audio.py`.
- Retain `ProjectExportMixin` on `MainWindow` as a clean facade to guarantee 100% backward compatibility for all existing callers.
