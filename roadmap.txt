RADIO & TV STORY SEGMENTER - DEVELOPMENT ROADMAP & TECHNICAL SPECIFICATION
================================================================================
This document outlines the architectural roadmap and implementation specifications
for future versions of the Radio & TV Story Segmenter. Adapted from best-in-class
heuristics, modular runtime architectures, and timeline serialization algorithms.

--------------------------------------------------------------------------------
ROADMAP MAINTENANCE POLICY: N-1 SLIDING-WINDOW & STATUS TRACKING
--------------------------------------------------------------------------------
- The roadmap maintains a rolling window: it displays the current/immediate past
  release ($N-1$) for baseline context, followed by active upcoming development
  milestones ($N$, $N+1$).
- Status Notation Policy (Modeled after Social Digest):
  * All milestones and feature items are annotated with explicit progress indicators:
    - [x] Completed item / feature
    - [-] In-progress item / active development
    - [ ] Planned / not started item
  * When work commences on an item, mark it immediately as [-] [IN-PROGRESS].
  * Mark an item as [x] [COMPLETED] when implementation is finalized, upon user
    confirmation, or inferred when development transitions to another part of the roadmap.
- When a new version is built, its completed specifications are recorded, and any
  versions older than $N-1$ are pruned to keep the document focused and actionable.
- Whenever any code change, bug fix, packaging adjustment, or feature refinement is
  made during a release cycle, it MUST be recorded immediately in the current release
  section of roadmap.txt and CHANGELOG.md (even if it occurs after the initial version
  number bump).

[x] 1.1 Acoustic Voice Profile Refinement & Pre-Caching Engine (`transcript_story.py`, `speaker_identity.py`)
-------------------------------------------------------------------------------------------------------------
- Pre-caching candidate turn vectors via `_ensure_candidate_cache`, completely eliminating redundant WeSpeaker ONNX / ffmpeg audio re-extractions during threshold slider scrubs.
- Dynamic match tooltip with competitor separation margin: Displays target acoustic similarity, closest competitor similarity, and separation margin (e.g. `Similarity: 88.4% | Nearest competitor: 72.1% (separation: +16.3%)`).
- In-place keyboard shortcuts: Added `Return`, `Enter`, and `X` shortcuts to toggle candidate inclusion checkboxes directly while navigating the candidate table with keyboard arrow keys.
- Robust profile synthesis & competitor target separation: Synthesize target profile via `robust_reference_profile` and exclude target speaker turns from competitor comparison sets.
- Session voice profile auto-enrollment: Automatically enrolls verified speaker turn embeddings into the active session voice profile cache (`_session_speaker_profiles`) upon applying acoustic voice identification.

[x] 1.2 Competitive Rapid Dialog Turn Classifier & Anchor Refinement (`transcript_story.py`, `transcript_editor.py`)
---------------------------------------------------------------------------------------------------------------------
- Interactive refinement tool (`prompt_refine_speaker_run`) and context menu integration for rapid dialogue turns between two confirmed anchor speakers.
- Computes relative acoustic distance against both speaker centroids and classifies each turn to the closer speaker, with automatic sample enrollment if explicit profiles are not yet cached.

[x] 1.3 Subtitle/Speaker Alignment Diagnostic Test Suite Alignment (`test_runner.py`)
-------------------------------------------------------------------------------------
- Synchronized `DiagnosticEngine` unit tests (`_test_audio_subtitle_sync`, `_test_transcription_subtitle_export_parity`) with updated speaker detection logic, strict timestamp bounds, and modern formatting standards.
- All 27 diagnostic test suites pass cleanly with 100% test suite fidelity.
