--------------------------------------------------------------------------------
ROADMAP MAINTENANCE POLICY: N-1 SLIDING-WINDOW & STATUS TRACKING
--------------------------------------------------------------------------------
- The roadmap maintains a rolling window: it displays the current/immediate past
  release ($N-1$) for baseline context, followed by active upcoming development
  milestones ($N$, $N+1$).
- Status Notation Policy (Modeled after Social Digest):
  * All milestones and feature items are annotated with explicit progress indicators:
    - [x] Completed item / feature
    - [-] In-progress item / active development
    - [ ] Planned / not started item
  * When work commences on an item, mark it immediately as [-] [IN-PROGRESS].
  * Mark an item as [x] [COMPLETED] when implementation is finalized, upon user
    confirmation, or inferred when development transitions to another part of the roadmap.
- When a new version is built, its completed specifications are recorded, and any
  versions older than $N-1$ are pruned to keep the document focused and actionable.
- Whenever any code change, bug fix, packaging adjustment, or feature refinement is
  made during a release cycle, it MUST be recorded immediately in the current release
  section of roadmap.txt and CHANGELOG.md (even if it occurs after the initial version
  number bump).

1. PREVIOUS RELEASE: STABILITY, SECURITY, ASYNC PROVISIONING & HALLUCINATION SCRUBBER (Completed in v3.2.1-dev)
================================================================================

[x] 1.1 OS-LEVEL CHILD PROCESS BINDING (WINDOWS JOB OBJECTS & POSIX PROCESS GROUPS)
------------------------------------------------------------------------------------
- Bound application and all child worker processes (`python.exe`, `ffmpeg.exe`, translation/diarization workers) to an OS Job Object (`JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`) on Windows and isolated process groups on POSIX, eliminating orphaned background processes on crash or Task Manager termination.

[x] 1.2 TRANSLATION PLUGIN SELF-CONTAINMENT & PURE CTRANSLATE2 ISOLATION
------------------------------------------------------------------------
- Stripped `torch` and Hugging Face `transformers` dependencies from `plugins/translation/`, standardizing model loading exclusively on quantized `ctranslate2.Translator` and `sentencepiece` for minimal memory and disk footprint.

[x] 1.3 EMERGENCY UNHANDLED EXCEPTION PROJECT SNAPSHOT & CRASH RECOVERY
------------------------------------------------------------------------
- Updated `excepthook` in `playback_preferences.py` to serialize project state to `<project_file>.crash_recovery.rtvs` upon unhandled exceptions, with automated recovery prompts on subsequent launches.

[x] 1.4 UNIFIED CORE ASYNC RUNTIME PROVISIONER (RUNTIMEMANAGER ENGINE)
-----------------------------------------------------------------------
- Consolidated background virtual environment creation and package installation into `runtime_manager.py` with `threading.Event` cancellation, non-blocking subprocess polling, and responsive dialog workers.

[x] 1.5 WHISPER HALLUCINATION & DEGENERATE LOOP SCRUBBER
---------------------------------------------------------
- Implemented `collapse_repeating_ngrams`, `strip_hallucination_phrases`, and `trim_trailing_degenerate_tail` in `prs_shared.py` to automatically prune repetitive degenerate loops and standard ASR artifacts from generated transcripts.

2. CURRENT RELEASE: UPDATE REPOSITORY MIGRATION, DEAD CODE PRUNING & ARCHITECTURAL CLEANUP (Completed in v3.2.2-beta)
================================================================================

[x] 2.1 AUTOMATIC GITHUB UPDATE REPOSITORY MIGRATION TO `bradlinder/RTVS3`
-------------------------------------------------------------------------
- Implemented automated migration inside `get_github_repo()` (`prs_shared.py`, `updater.py`, `utils/constants.py`) to detect legacy saved repository keys (`bradlinder/RTVS`, `bradlinder/RadioTVStorySegmenter`) in user `QSettings` and seamlessly upgrade them to `bradlinder/RTVS3`.
- Updated hardcoded `"bradlinder/RTVS"` defaults in `playback_preferences.py` ("Restore Defaults" for Software Updates) to use `DEFAULT_GITHUB_REPO`.
- Added repository normalization on preferences save and upon initializing the Check for Updates dialog to prevent stale update queries against deprecated repositories.

[x] 2.2 DEAD CODE & ORPHANED DIALOG MODULE PRUNING
---------------------------------------------------
- Removed obsolete `models.py` (185 lines of unused dataclasses replaced by native dictionaries in `prs_shared.py`).
- Pruned redundant dialog duplicates in `ui/dialogs/` (`find_replace.py` and `comment_editor.py`), eliminating the orphaned `ui/` directory tree.
- Removed committed 12 KB binary archive artifact `plugins/translation/translation.rtvs-addon` from the source repository.

[x] 2.3 ARCHITECTURAL INVARIANT DECOUPLING & IMPORT CONSOLIDATION
------------------------------------------------------------------
- Replaced top-level plugin import `YouTubeAssistedUploadGuideDialog` in `project_export.py` with lazy, guarded import inside `export_youtube_bundle`, enforcing the invariant that core modules must not import from `plugins/` on startup.
- Updated `export/docx.py` to import `format_time` directly from `prs_shared.py`, removing the sole external import dependency on `utils.time_format`.
- Cleaned vestigial `torch_mod` parameters and returns in `plugins/translation/worker.py` following pure CTranslate2 engine isolation.
