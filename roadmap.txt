RADIO & TV STORY SEGMENTER - DEVELOPMENT ROADMAP & TECHNICAL SPECIFICATION
================================================================================
This document outlines the architectural roadmap and implementation specifications
for future versions of the Radio & TV Story Segmenter. Adapted from best-in-class
heuristics, modular runtime architectures, and timeline serialization algorithms.

--------------------------------------------------------------------------------
ROADMAP MAINTENANCE POLICY: N-1 SLIDING-WINDOW & STATUS TRACKING
--------------------------------------------------------------------------------
- The roadmap maintains a rolling window: it displays the current/immediate past
  release ($N-1$) for baseline context, followed by active upcoming development
  milestones ($N$, $N+1$).
- Status Notation Policy (Modeled after Social Digest):
  * All milestones and feature items are annotated with explicit progress indicators:
    - [x] Completed item / feature
    - [-] In-progress item / active development
    - [ ] Planned / not started item
  * When work commences on an item, mark it immediately as [-] [IN-PROGRESS].
  * Mark an item as [x] [COMPLETED] when implementation is finalized, upon user
    confirmation, or inferred when development transitions to another part of the roadmap.
- When a new version is built, its completed specifications are recorded, and any
  versions older than $N-1$ are pruned to keep the document focused and actionable.
- Whenever any code change, bug fix, packaging adjustment, or feature refinement is
  made during a release cycle, it MUST be recorded immediately in the current release
  section of roadmap.txt and CHANGELOG.md (even if it occurs after the initial version
  number bump).

CORE ARCHITECTURAL INVARIANTS
================================================================================
- Core modules must NEVER import from plugins/.
- Heavy translation runtimes must remain isolated inside plugins/translation/.
- Speaker diarization uses wespeakerruntime as the primary ONNX embedding engine.
- Real-time progress updates with percentage, status messages, and estimated time.
- Diagnostic logs written to OS standard logging locations.
- Offline-first architecture: core processing functions locally without internet.
- 0 MB Default GPU Footprint: Base installer contains 0 MB of CUDA bloat; GPU features are purely optional and provisioned on demand.

2. CURRENT RELEASE: MACOS SYSTEM CLI & HOMEBREW PATH INTEGRATION, ROBUST SSL CONTEXT, & SUBPROCESS HARDENING (Completed in v3.2.20)
================================================================================

[x] 2.1 MACOS SYSTEM CLI & HOMEBREW PATH ENVIRONMENT INTEGRATION
-------------------------------------------------------------------
- Implemented `setup_macos_path_environment()` in `bootstrap.py` and `radio_tv_story_segmenter_worker.py` to ensure standard macOS tool directories (`/opt/homebrew/bin`, `/opt/homebrew/sbin`, `/usr/local/bin`, `/usr/local/sbin`, `~/.local/bin`, `~/.cargo/bin`) are present in `os.environ["PATH"]`.
- Applications launched from macOS Finder / Dock / Spotlight run under `launchd` with a stripped-down `PATH` (`/usr/bin:/bin:/usr/sbin:/sbin`), which previously made Homebrew-installed `ffmpeg`, `ffprobe`, `python3`, and `uv` invisible.
- Enhanced `find_bundled_executable()` in `prs_shared.py` to directly search Homebrew and standard macOS bin directories if not found on `PATH`.

[x] 2.2 ROBUST SSL CONTEXT FACTORY (KEYWORD ARGUMENT HANDLING)
-----------------------------------------------------------------
- Fixed a critical `TypeError: <lambda>() got an unexpected keyword argument 'purpose'` bug in `bootstrap.py` and `plugins/translation/support.py` where `ssl._create_default_https_context` was previously assigned a 0-argument lambda. Replaced with a flexible context factory accepting all keyword arguments (`purpose`, `cafile`, `capath`, `cadata`), ensuring downstream libraries (`requests`, `urllib3`, `pip`, `huggingface_hub`) never crash during SSL handshakes.

[x] 2.3 WORKER SUBPROCESS ENVIRONMENT HARDENING & OPENMP SAFETY
------------------------------------------------------------------
- Enhanced `_apply_worker_env_overrides()` in `processing.py` and `_launch_translation_process()` in `translation.py` to automatically propagate `KMP_DUPLICATE_LIB_OK`, `TOKENIZERS_PARALLELISM`, `HF_HUB_DISABLE_SYMLINKS_WARNING`, SSL certificate bundles, and Homebrew `PATH` into `QProcessEnvironment` across all worker subprocesses.

[x] 2.4 WESPEAKER DEPENDENCY & GATEKEEPER QUARANTINE CLEARANCE
-----------------------------------------------------------------
- Added `"wespeakerruntime>=1.0.0,<2.0.0"` to `ENV_CONFIGS["diarize"]["packages"]` in `runtime_manager.py` to ensure fresh diarization environments automatically install the required ONNX voice embedding engine.
- Added recursive Gatekeeper quarantine removal (`_remove_macos_quarantine(env_dir)`) upon isolated virtual environment creation in `runtime_manager.py` to prevent macOS from terminating child processes or dylibs with `SIGKILL` (Killed: 9).

3. UPCOMING MILESTONE: STORY AUDIO FADE-IN/OUT & PER-STORY ENVELOPE CONTROLS (Phase 3.5 - Planned for v3.3) [NOT STARTED]
================================================================================

[ ] 3.1 GLOBAL & EXPORT-TIME FADE CONTROLS WITH PERFORMANCE NOTICE
-------------------------------------------------------------------
- Add an explicit toggle in the Unified Export Dialog (`export/dialog.py`) next to media format options: `[x] Apply audio fade envelopes (In/Out)`.
- Include prominent, helpful helper text/tooltip in the UI: *"Audio re-encoding required; media export may take longer than direct stream copy."*
- Always available as an option across both Voice detection mode and Music/Song mode without restriction.

[ ] 3.2 CONFIGURABLE DEFAULT FADE DURATIONS IN PREFERENCES
------------------------------------------------------------
- Expose dual configurable default duration spinboxes in `playback_preferences.py` under the Export settings tab:
  * Default Fade-In Duration: `0.0s` (Range: `0.0s` - `10.0s`)
  * Default Fade-Out Duration: `1.0s` (Range: `0.0s` - `10.0s`)
- Values persisted to user preferences via `QSettings` and automatically applied as default properties when creating or detecting stories.

[ ] 3.3 INTERACTIVE TIMELINE FADE HANDLES (DUAL CORNER MANIPULATION)
----------------------------------------------------------------------
- Add dual tactile drag-and-drop fade handles to each story block in the waveform/timeline canvas:
  * Top-Left Corner: Fade-In handle (drag rightward to lengthen fade-in ramp).
  * Top-Right Corner: Fade-Out handle (drag leftward to lengthen fade-out ramp).
- Hovering within 8px of either top corner activates a horizontal sizing cursor (`Qt.SizeHorCursor`).
- Real-time rendering of diagonal/curved fade envelope overlays directly on the waveform showing exact attenuation boundaries.

[ ] 3.4 PER-STORY FADE DURATIONS VIA STORIES MENU & CONTEXT MENU
-----------------------------------------------------------------
- Provide sample-accurate numerical entry dialog via right-click context menu on a story (`Set Audio Fades...`) and under the main Stories menu.
- Displays separate precision spinboxes for Fade-In (s) and Fade-Out (s) with quick presets (`None`, `0.5s`, `1.0s`, `2.0s`, `Reset to Preferences`).

[ ] 3.5 CHAINED FFMPEG AUDIO FILTER PIPELINE INTEGRATION
----------------------------------------------------------
- Update `extract_media()` in `project_export.py` to evaluate both `fade_in_duration` and `fade_out_duration`.
- Constructs chained audio filter arguments dynamically:
  * If both: `-af "afade=t=in:st=0:d={in_dur:.3f},afade=t=out:st={duration - out_dur:.3f}:d={out_dur:.3f}"`
  * If in only: `-af "afade=t=in:st=0:d={in_dur:.3f}"`
  * If out only: `-af "afade=t=out:st={duration - out_dur:.3f}:d={out_dur:.3f}"`
- Keeps video tracks stream-copied (`-c:v copy`) for video containers (`.mp4`, `.mov`), re-encoding only the audio stream to native container formats (`aac`, `libmp3lame`, `pcm_s16le`).
