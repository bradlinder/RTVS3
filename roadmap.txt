This document outlines the architectural roadmap and implementation specifications

--------------------------------------------------------------------------------
ROADMAP MAINTENANCE POLICY: N-1 SLIDING-WINDOW & STATUS TRACKING
--------------------------------------------------------------------------------
- The roadmap maintains a rolling window: it displays the current/immediate past
  release ($N-1$) for baseline context, followed by active upcoming development
  milestones ($N$, $N+1$).
- Status Notation Policy (Modeled after Social Digest):
  * All milestones and feature items are annotated with explicit progress indicators:
    - [x] Completed item / feature
    - [-] In-progress item / active development
    - [ ] Planned / not started item
  * When work commences on an item, mark it immediately as [-] [IN-PROGRESS].
  * Mark an item as [x] [COMPLETED] when implementation is finalized, upon user
    confirmation, or inferred when development transitions to another part of the roadmap.
- When a new version is built, its completed specifications are recorded, and any
  versions older than $N-1$ are pruned to keep the document focused and actionable.
- Whenever any code change, bug fix, packaging adjustment, or feature refinement is
  made during a release cycle, it MUST be recorded immediately in the current release
  section of roadmap.txt and CHANGELOG.md (even if it occurs after the initial version
  number bump).

[x] 2.1 Refine Rapid Dialog Turn Context & Timestamp Redesign (`prompt_refine_speaker_run` in `transcript_story.py`)
--------------------------------------------------------------------------------
- Replaced raw numeric segment index spinboxes with rich dropdown selectors displaying formatted timestamps, speaker labels, and spoken text snippets for both Start and End turns (e.g. `[00:14.200] Turn #4 (Leticia): “Hello, how are you today…”`).
- Added an interactive live range & context preview card displaying turn counts, time spans, durations, and boundary quote snippets that updates synchronously when dropdown items change.
- Automated bounds normalization (`min(s_i, e_i), max(s_i, e_i)`) ensuring seamless execution regardless of selection order.

[x] 2.2 Speakers & Detection Clusters Table Ergonomics & Legibility (`SpeakerManagerDialog` in `transcript_story.py`)
--------------------------------------------------------------------------------
- Normalized table row heights (`setRowHeight(row, 46)`), set vertical header default section size to 46px, and allocated a fixed 240px width to column 4.
- Restyled "Rename / Alias" and "Merge Into..." buttons with crisp typography, high-contrast dark slate backgrounds, rounded borders, 26px minimum height, and pointing hand cursors to eliminate vertical button clipping and ensure effortless legibility.

[x] 2.3 Acoustic Voice Profile Matcher Performance & Fluidity (`VoiceProfileMatchDialog` & `find_matching_voice_turns` in `transcript_story.py`)
--------------------------------------------------------------------------------
- Implemented 60ms single-shot debouncing for similarity threshold slider scrubbing, decoupling immediate label updates from heavy table updates for fluid 60+ FPS responsiveness.
- Precomputed base competitor centroids and top-turn sets in `find_matching_voice_turns` outside the candidate loop, eliminating redundant 256-dimensional vector calculations.
- Optimized table population with `setUpdatesEnabled(False)` and pre-allocated row counts (`setRowCount(len(self.matched_turns))`) to eliminate layout thrashing.
- Guarded audio player seeking during table updates to suppress spurious player seeks.
- Preserved user turn deselections across sensitivity adjustments via `_user_deselected_ids`.
