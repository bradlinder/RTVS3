RADIO & TV STORY SEGMENTER - DEVELOPMENT ROADMAP & TECHNICAL SPECIFICATION
================================================================================
This document outlines the architectural roadmap and implementation specifications
for future versions of the Radio & TV Story Segmenter. Adapted from best-in-class
heuristics, modular runtime architectures, and timeline serialization algorithms.

--------------------------------------------------------------------------------
ROADMAP MAINTENANCE POLICY: N-1 SLIDING-WINDOW & STATUS TRACKING
--------------------------------------------------------------------------------
- The roadmap maintains a rolling window: it displays the current/immediate past
  release ($N-1$) for baseline context, followed by active upcoming development
  milestones ($N$, $N+1$).
- Status Notation Policy (Modeled after Social Digest):
  * All milestones and feature items are annotated with explicit progress indicators:
    - [x] Completed item / feature
    - [-] In-progress item / active development
    - [ ] Planned / not started item
  * When work commences on an item, mark it immediately as [-] [IN-PROGRESS].
  * Mark an item as [x] [COMPLETED] when implementation is finalized, upon user
    confirmation, or inferred when development transitions to another part of the roadmap.
- When a new version is built, its completed specifications are recorded, and any
  versions older than $N-1$ are pruned to keep the document focused and actionable.
- Whenever any code change, bug fix, packaging adjustment, or feature refinement is
  made during a release cycle, it MUST be recorded immediately in the current release
  section of roadmap.txt and CHANGELOG.md (even if it occurs after the initial version
  number bump).

CORE ARCHITECTURAL INVARIANTS
================================================================================
- Core modules must NEVER import from plugins/.
- Heavy translation runtimes must remain isolated inside plugins/translation/.
- Speaker diarization uses wespeakerruntime as the primary ONNX embedding engine.
- Real-time progress updates with percentage, status messages, and estimated time.
- Diagnostic logs written to OS standard logging locations.
- Offline-first architecture: core processing functions locally without internet.
- 0 MB Default GPU Footprint: Base installer contains 0 MB of CUDA bloat; GPU features are purely optional and provisioned on demand.

1. PREVIOUS RELEASE: CPU-FIRST DIARIZATION & TRANSLATION, CUDA PRUNING & INSTALLER CACHE (Completed in v3.2.4)
================================================================================

[x] 1.1 TRANSLATION & DIARIZATION RUNTIME CUDA REMOVAL
------------------------------------------------------
- Stripped all unused CUDA/cuDNN dependencies from both the isolated translation (`runtimes/translate`) and diarization (`runtimes/diarize`) environments.
- Enforced PyTorch CPU wheel index (`https://download.pytorch.org/whl/cpu`) in `ENV_CONFIGS`, reducing environment footprints by over 1.4 GB per environment.
- Preserved 100% INT8 translation performance using CPU-optimized CTranslate2 execution and fast ONNX WeSpeaker diarization.
- Bumped isolated translate environment version to `2.9` and diarize environment version to `1.1.0`.

[x] 1.2 AUTOMATED RUNTIME CUDA PRUNING
--------------------------------------
- Added `RuntimeManager.prune_cuda_artifacts(env_dir)` to systematically delete heavy NVIDIA directories (`**/nvidia`) and loose CUDA libraries (`libnvrtc*`, `libcudnn*`, `libcublas*`, `torch_cuda*`, etc.).
- Integrated automated pruning across `translate` and `diarize` runtimes in `RuntimeManager.ensure_environment` and `model_management.py` upon inspection and post-install.

[x] 1.3 APPDATA INSTALLER CACHE MANAGEMENT & AUTOMATIC CLEANUP
-------------------------------------------------------------
- Implemented `cleanup_old_installers(max_to_keep=1, force_all=False)` in `updater.py` to scan `AppData/updates` (and macOS/Linux app data directories) and delete outdated installer binaries (`.exe`, `.dmg`, `.pkg`, `.deb`, `.rpm`, `.AppImage`, `.zip`, `.tar.gz`) and orphaned `.download` files.
- Hooked automated cleanup into app startup, background update checks, download completion, and the Check for Updates dialog.
- Added Downloaded Update Installers inspection, size tracking, and deletion to `model_management.py` and connected it to `purge_all_data()`.

[x] 1.4 DOCUMENTATION & BUILD SPECIFICATION SYNCHRONIZATION
-----------------------------------------------------------
- Synchronized `README.md`, `BUILD_INSTRUCTIONS.txt`, `STABILITY_NOTES.md`, and `ARCHITECTURE.md` to document CPU-first architecture for translation and diarization and clarify optional Whisper GPU acceleration.

2. CURRENT RELEASE: PREFERENCES GPU ACCELERATION & OPTIONAL CUDA (Completed in v3.2.6)
================================================================================

[x] 2.1 DEDICATED PREFERENCES GPU ACCELERATION PANEL
---------------------------------------------------
- Relocated GPU acceleration controls to a dedicated "GPU Acceleration" category in the Preferences dialog (`Settings > Preferences > GPU Acceleration`).
- Integrated live hardware inspection via `detect_nvidia_gpu` displaying real-time NVIDIA card detection status and environment installation state.
- Added direct action buttons to download/install the runtime or completely uninstall it to reclaim disk space.

[x] 2.2 GRANULAR CUDA TOOL TOGGLES
----------------------------------
- Implemented independent checkboxes for every CUDA-capable tool:
  * Master Enable GPU Acceleration switch.
  * Faster-Whisper ASR transcription acceleration.
  * MarianMT / OPUS-MT neural machine translation (via CTranslate2 on CUDA).
  * WeSpeaker speaker detection and diarization (via ONNX Runtime GPU / `CUDAExecutionProvider`).
- Configured dynamic environment variable dispatch (`PRS_WHISPER_DEVICE`, `PRS_TRANSLATE_DEVICE`, `PRS_DIARIZE_DEVICE`) so workers automatically execute on the requested compute device.

[x] 2.3 100% OPTIONAL ZERO-DISK FOOTPRINT ARCHITECTURE
------------------------------------------------------
- The base distribution installer is 100% CPU-first, containing 0 MB of CUDA packages or NVIDIA libraries.
- CUDA packages (`torch` cu121, `ctranslate2`, `onnxruntime-gpu`, `wespeakerruntime`) are installed strictly into an isolated virtual environment (`gpu_transcribe`) only when explicitly triggered by the user.
- Disabling or uninstalling the feature completely frees the environment directory, guaranteeing 0 MB disk consumption when inactive.
- CPU execution paths remain completely intact as reliable fallbacks on all platforms.

[x] 2.4 QUICK-ACCESS DATA & MODEL PURGE ACTION
----------------------------------------------
- Added "Purge All Downloaded Models & Cache Data…" to the top-level Tools menu (`Tools > Purge All Downloaded Models & Cache Data…`).
- Added matching "Purge All Downloaded Models & Cache Data…" button in the Preferences AI Models page.
- Provides immediate one-click deletion of all downloaded Whisper ASR models, translation models, updater installer cache, log files, and optional runtimes.
