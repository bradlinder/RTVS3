ROADMAP MAINTENANCE POLICY: N-1 SLIDING-WINDOW & STATUS TRACKING
--------------------------------------------------------------------------------
- The roadmap maintains a rolling window: it displays the current/immediate past
  release ($N-1$) for baseline context, followed by active upcoming development
  milestones ($N$, $N+1$).
- Status Notation Policy (Modeled after Social Digest):
  * All milestones and feature items are annotated with explicit progress indicators:
    - [x] Completed item / feature
    - [-] In-progress item / active development
    - [ ] Planned / not started item
  * When work commences on an item, mark it immediately as [-] [IN-PROGRESS].
  * Mark an item as [x] [COMPLETED] when implementation is finalized, upon user
    confirmation, or inferred when development transitions to another part of the roadmap.
- "WHAT'S NEXT" SINGLE-STEP EXECUTION RULE FOR AI STUDIO (GEMINI 3.8 FLASH):
  * Whenever the user asks "what's next" (or asks to continue the roadmap), execute
    ONLY the single next uncompleted `[ ]` or in-progress `[-]` sub-item (e.g., 3.2,
    then stop and wait for the next prompt before doing 3.3).
  * NEVER combine multiple sub-items in a single response.
  * NEVER truncate any file with placeholders (`# ... existing code ...`).
  * ALWAYS preserve 100% backward compatibility by re-exporting all extracted classes,
    functions, and constants in the original facade module and `prs_shared.py`.
  * ALWAYS keep every new or modified `.py` file under the 1,000-line ceiling (~800 lines target).
- Whenever any code change, bug fix, packaging adjustment, or feature refinement is
  made during a release cycle, it MUST be recorded immediately in the current release
  section of roadmap.txt and CHANGELOG.md (even if it occurs after the initial version
  number bump).

      2. Parses `Integrated Loudness (I)` in LUFS, `Loudness Range (LRA)` in LU, and `True Peak (TP)` in dBTP/dBFS.

[ ] 4.2 Conditional Two-Tier Hybrid Normalization Pipeline (`audio_normalization.py`)
    - Implement `normalize_audio_sidecar(media_path, report, target_lufs=-16.0, max_true_peak=-1.5) -> Path`:
      1. Bypass Condition: If `report.integrated_lufs >= (target_lufs - 2.0)` and `report.true_peak_dbtp <= -0.5`, skip normalization and return the original path (`needs_boost = False`) to avoid unnecessary disk I/O.
      2. Tier 1 — Linear Gain + True-Peak Limiter (Default for uniform quiet audio, `LRA <= 14.0 LU`): Apply exact linear gain `delta_db = min(target_lufs - report.integrated_lufs, 24.0)` followed by a transparent brickwall limiter (`-af "volume={delta_db}dB,alimiter=limit=-1.5dB:level=false"`) so speech dynamics remain 100% natural without single-pass `loudnorm` pumping artifacts.
      3. Tier 2 — Dynamic Speech Leveler (For extreme speaker disparity, `LRA > 14.0 LU`, e.g., loud studio host + quiet phone-in guest): Apply speech-tuned dynamic normalization (`-af "highpass=f=80,dynaudnorm=f=250:g=15:p=0.89:m=10.0,alimiter=limit=-1.5dB:level=false"`).
      4. Automatically feed the normalized sidecar WAV into `transcription_processing.py` and `diarization_processing.py` when enabled.
