# Changelog

## v3.9.96-beta
- **WordPress Episode Backfill, Update Existing Post Mode & Publication Date Scheduling (`plugins/wordpress/episode_updater.py`, `plugins/wordpress/client.py`, `plugins/wordpress/export_destination.py`, `plugins/wordpress/wp_ui_builder.py`, `plugins/wordpress/wp_tab_widget.py`, `plugins/wordpress/wp_post_builder.py`, `plugins/wordpress/plugin.py`, `diagnostic_export_tests.py`)**:
  - **Purpose & Architectural Overview**:
    - Built to let producers backfill older WordPress broadcast/podcast episode pages (e.g., `https://rss.phillycam.org/april-29-2026/`) that already have a live URL, a full-episode MP3 file, Seriously Simple Podcasting (Castos) RSS feed metadata, and short summary text on the page—transforming them to match brand-new segmented exports (a Full Episode page with a full transcript and linked story index, plus individual Story pages with segmented MP3 clips and transcripts) **without** breaking existing permalinks, unpublishing live episodes, altering Castos RSS enclosures/`<guid>` identifiers, or losing human-written show notes/archive excerpts.
    - Designed to preserve backward compatibility with all existing local-file, single-story, and multi-story draft export workflows while keeping new logic isolated in `plugins/wordpress/episode_updater.py` (Single Responsibility compliant).
  - **Two-Mode Workflow Toggle (`plugins/wordpress/episode_updater.py`, `wp_ui_builder.py`, `wp_tab_widget.py`)**:
    - Added a **Workflow Mode** selector at the top of the WordPress configuration panel (`setup_wp_mode_and_date_ui`):
      1. **`Create New Episode & Stories` (Default)**: Creates new posts as `Draft`, uploads MP3 audio and Castos metadata as configured, and leaves the existing-URL lookup panel hidden.
      2. **`Update Existing Episode & Backfill Stories`**: Reveals the **Existing Post URL** panel, defaults the Full Episode to **update in place** while preserving its `Published` status and existing MP3/Castos metadata (`replace_existing_audio=False`), keeps child Stories as backdated `Draft` posts with uploaded story MP3 clips, and switches the export button label (`WordPressExportDestination.button_label`) to `"Update Episode & Export Story Drafts..."` / `"Update Existing WordPress Post"`.
  - **Shared Publication Date & Time Scheduling in Both Modes (`normalize_wp_iso_date`, `wp_pub_date_edit`)**:
    - Added a shared **Publication Date** field (`YYYY-MM-DD`, `YYYY-MM-DD HH:MM`, or `MM/DD/YYYY` normalized to WordPress ISO-8601 `YYYY-MM-DDTHH:MM:SS`) visible in **both** `Create New Episode` and `Update Existing Episode` modes.
    - When left blank, `date` is omitted from REST payloads so WordPress uses the current date and time; when populated (manually or auto-filled from an existing episode URL), the timestamp is applied consistently to both the Full Episode and every Story created in that batch.
  - **Option B Show-Notes & Archive Excerpt Preservation (`resolve_wp_post_from_url`, `clean_html_to_plain_excerpt`)**:
    - Older manually published WordPress episodes frequently store their teaser/show notes inside the main post body (`post_content`) while leaving `post_excerpt` empty (causing WordPress archives and Seriously Simple Podcasting RSS feeds to auto-pull the first words of `post_content`). Replacing the post body with a raw transcript would overwrite those show notes on archive cards and in podcast apps.
    - When `resolve_wp_post_from_url()` fetches an existing post (via `GET /wp/v2/posts?slug=...&status=any&context=edit`, falling back cleanly across query/CPT endpoints and `?p=`/`post=` IDs), if `excerpt.raw` is empty, `clean_html_to_plain_excerpt()` strips block comments, shortcodes, and `<audio>`/`<video>`/`<iframe>` tags from the existing post body and moves that original text into the WordPress `Excerpt` field (`excerpt_from_existing=True`).
    - Added `_excerpt_user_edited` tracking in `wp_tab_widget.py` so manual user edits are respected, and protected existing episode show notes in `_autofill_all_excerpts()` so clicking **"Auto-fill All Excerpts"** generates 55-word excerpts for Story posts without clobbering the Full Episode's preserved show notes.
  - **Full Episode Audio & Podcast RSS Safeguards (`client.py`, `export_destination.py`)**:
    - Added `existing_post_id`, `replace_existing_audio_and_podcast`, `post_status`, `publication_date`, and `post_slug` parameters to `execute_wordpress_upload()`, plus `date`, `slug`, `author_ids`, `author_term_ids`, and schema-sanitized `meta`/taxonomy fallbacks to `WordPressClient.create_post()` and `WordPressClient.update_post()`.
    - When `existing_post_id` is set and `replace_existing_audio_and_podcast=False`, `execute_wordpress_upload()` skips FFmpeg conversion, skips `/wp/v2/media` audio uploads, omits duplicate `<!-- wp:audio -->` blocks, omits Castos `meta` and `podcast_series` keys (leaving the existing MP3 enclosure and podcast RSS feed intact), and calls `client.update_post()` in-place without overwriting the permalink `slug` or unpublishing the episode—while still generating, fading, and uploading individual MP3 clips for the segmented Story posts.
    - Updated `WordPressExportDestination.execute_export()` to auto-resolve pasted `existing_post_url` targets on export (aborting that item safely rather than creating an accidental duplicate post if resolution fails), bypass the `"Podcast Audio File Required"` prompt when preserving existing Full Episode audio, and always capture the updated Full Episode's ID and generated content so the **"Stories in this Episode"** Table of Contents is appended properly.
  - **Post Status Controls & Clean Permalink Slugs for TOC Cross-Linking (`build_story_slug`)**:
    - Added explicit **Full Episode** (`Draft` / `Published (Keep Live)`) and **Stories** (`Draft` / `Published`) status dropdowns so live episodes remain published (`publish`) while newly created Story pages default to `draft` with the episode's publication date.
    - Assigned deterministic URL slugs via `build_story_slug()` when creating new Story posts and resolved clean canonical links (`{site_url}/{slug}/`) inside the Full Episode's Table of Contents whenever the Full Episode is published (`publish`) and WordPress returned a temporary `?p=<id>` draft preview URL.
  - **Dual MP3 Loading Workflows & Top-Level File Menu Integration (`plugin_base.py`, `ui_menus.py`, `episode_updater.py`, `plugins/wordpress/plugin.py`)**:
    - Added `BasePlugin.get_file_open_actions()` in `plugin_base.py` and wired `MenuManager.refresh_plugin_menus()` in `ui_menus.py` to insert enabled plugin media-open actions directly inside the top-level **File** menu's Media Input section (above the first separator).
    - Exposed **`File > Open Existing WordPress Episode...`** (and matching export-menu entry via `Plugin.get_file_open_actions()` / `Plugin.get_export_actions()`) so users can start a backfill project cleanly from a brand-new session without opening the Export dialog first.
    - Enhanced `LoadWordPressEpisodeDialog` with a **Fetch Info** metadata preview and three audio loading options: **Download and load MP3 from WordPress episode / URL** (discovered from Castos post meta `audio_file`/`ss_podcast_audio_file`, `enclosure`, rendered content, or public page HTML, plus direct `.mp3`/audio URL detection), **Use local audio file from computer** (with `Browse...` picker paired with the fetched WordPress episode metadata), and **Load WordPress episode metadata only**; also kept **"Download & Load Episode MP3"** inside the WordPress export panel. All paths automatically switch the project into `Update Existing Episode` mode with pre-populated metadata.
  - **Story-Only Category Sync & Context-Aware Audio Checkbox (`wp_ui_builder.py`, `wp_tab_widget.py`, `episode_updater.py`)**:
    - Added `Apply to all stories (excludes Full Episode)` (`wp_cb_cats_apply_stories`, persisted via `wp_cats_apply_all_stories`) under **Categories** on the **Authors & Taxonomy** tab; visible only when a Story post is selected, it syncs category selections and `Clear` actions across all Story posts via `_sync_categories_to_all_stories()` without modifying the Full Episode's categories.
    - Added `sync_wp_audio_checkbox_label()` so the Media tab's `Include audio files...` checkbox dynamically reads **"Include audio files for new Story clips (existing Full Episode MP3 preserved)"** in Update mode (when preserving the existing Full Episode MP3) and clarifies that keeping it checked is required for segmented Story MP3 uploads.
  - **User Guide Updates (`docs/guides/getting_started_and_workflow.md`, `docs/guides/wordpress_exporting.md`, `embedded_guides.py`)**:
    - Updated the **Getting Started & End-to-End Workflow** guide (Section 1) and **Exporting to WordPress & Podcast Feeds** guide (Sections 3 and 6), plus their synchronized offline fallback strings in `embedded_guides.py`, to document `File > Open Existing WordPress Episode...`, the two Workflow Modes (`Create New Episode & Stories` vs. `Update Existing Episode & Backfill Stories`), shared `Publication Date` scheduling, per-target post status dropdowns, Option B show-notes excerpt promotion, Castos MP3/RSS preservation, and clean `{site_url}/{slug}/` TOC story links.
  - **Test Hardening & Diagnostic Coverage (`client.py`, `diagnostic_export_tests.py`)**:
    - Guarded `WordPressClient._discover_canonical_base()` against live network lookups under `RTVS_TEST_MODE` or `example.com` hosts so headless tests execute without 5-second HTTP timeouts.
    - Added automated unit and end-to-end integration tests in `_test_wordpress_castos_podcast_integration` and `_test_wordpress_multi_story_upload_and_ui_pluralization` (Test D) verifying URL/ID/slug parsing, Option B excerpt extraction, date normalization, Full Episode in-place updates without audio/Castos overwrite, backdated Story draft creation with audio uploads, and clean TOC slug linking.

## v3.9.95-beta
- **Windows Post-Update Elevation De-escalation & Context Menu Hardening (`installer/Windows/RadioTVStorySegmenter.iss`, `timeline_context_menus.py`, `background_workers.py`, `media_batch.py`, `diagnostic_editor_tests.py`)**:

  - **Timeline Context Menu Localization Fix (`timeline_context_menus.py`)**:
    - Resolved `NameError: name 'is_es' is not defined` in `show_timeline_context_menu` by properly assigning `is_es = vocab.is_es`.
    - Restored right-click context menu functionality on empty timeline canvas areas and story blocks across English and Spanish locales.
    - Added optional `exec_menu: bool = True` parameter to both `show_timeline_context_menu()` and `show_selection_context_menu()` allowing headless verification and automated testing without opening blocking modal loops.
  - **Waveform Worker Network & File Error Reporting (`background_workers.py`, `media_batch.py`)**:
    - Configured FFmpeg subprocess stderr capture in `WaveformWorker` (`-v error`, `stderr=subprocess.PIPE`).
    - Propagated exact FFmpeg failure causes (`error_message`) to `MediaBatchMixin._waveform_finished()` so network access denials, unreachable shares, or corrupt audio streams log explicit actionable error messages rather than silently failing with "produced no audio data".
  - **Diagnostic Test Bench Menu Traversal Guard (`diagnostic_editor_tests.py`)**:
    - Added automated context-menu building verification across English and Spanish in `_test_story_highlighting_smart_copy_and_glossary_engine`, guaranteeing all action labels, dynamic vocabulary interpolations, and locale variables are exercised in CI.
  - **Progressive Streaming Waveform Rendering (`background_workers.py`, `media_batch.py`, `timeline_widgets.py`, `timeline_painter.py`, `diagnostic_editor_tests.py`)**:
    - Added real-time rate-limited waveform peak streaming via `WaveformWorker.progress` signal (`Signal(list, float, int)`), emitting partial peak arrays every ~250ms during extraction.
    - Updated `timeline_painter.py` to index progressive peaks by absolute time math (`eff_pps = progressive_pps / (4 ** level_index)`), rendering peaks left-to-right along the center baseline at their exact timeline ruler coordinates as frames decode over SMB network shares.
    - Added live percentage completion badge to the timeline background status banner (`Generating audio waveform ({pct}%)...`).
    - Added comprehensive regression unit test in `diagnostic_editor_tests.py` verifying partial peak rendering, percentage badge updates, and clean state restoration upon completion.
