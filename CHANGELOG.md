# Changelog

## v3.10.34-beta
- **Harden QThread Teardown Across Plugin & YouTube Dialogs, Eliminate Single-Feed WordPress Open Stall & Bundle-Safe Guide Test (`plugins/github_dialog.py`, `plugins/manager_dialog.py`, `plugins/youtube/yt_import_dialog.py`, `plugins/wordpress/wp_tab_widget.py`, `diagnostic_speaker_cleanup_tests.py`, `diagnostics/editor_story_ui_tests.py`)**:
  - **Safe `QThread` Teardown in Plugin Store & Plugin Manager (`plugins/github_dialog.py`, `plugins/manager_dialog.py`)**: Added `_cleanup_workers()`, `reject()`, and `closeEvent()` to `GitHubPluginsDialog` and `PluginManagerDialog` to disconnect signals, request interruption, and cleanly detach in-flight fetch/download/batch worker threads on early dialog close.
  - **Safe `QThread` Teardown in YouTube Episode Import & `yt-dlp` Updater (`plugins/youtube/yt_import_dialog.py`)**: Added `_detach_or_wait_yt_worker()` and wired `reject()` / `closeEvent()` on `LoadYouTubeEpisodeDialog` plus post-`exec()` cleanup in `open_yt_dlp_updater_dialog()` so closing mid-probe, mid-download, or mid-update never destroys an active `QThread`.
  - **Eliminate Repeated Single-Feed WordPress HTTP Stall (`plugins/wordpress/wp_tab_widget.py`)**: Removed the `len(podcast_feeds) <= 1` condition in `_populate_wp_export_metadata()` so single-feed WordPress sites reuse cached categories, authors, and podcast feeds instead of making 3 synchronous UI-blocking HTTP calls every time the Export dialog opens.
  - **Bundle-Safe Test #78 & Plugin Manifest Catch-Up (`diagnostic_speaker_cleanup_tests.py`, `diagnostics/editor_story_ui_tests.py`, `plugins/wordpress/manifest.json`, `plugins/youtube/manifest.json`)**: Updated Test #78 guide path lookup to check `_MEIPASS` and macOS `.app` `Resources/docs`, added teardown regression assertions, and synchronized/repackaged the WordPress and YouTube plugin bundles to `3.10.34-beta`.

## v3.10.33-beta
- **Fix In-App Diagnostic Test Bench Freeze at 69/82 + Real-App Dialog Worker Teardown (`updater_dialog.py`, `export/dialog.py`, `plugins/wordpress/wp_tab_widget.py`, `plugins/youtube/yt_import_dialog.py`, `cache_manager.py`, `diagnostic_dialog.py`, `diagnostics/editor_story_ui_tests.py`)**:
  - **Safe `CheckUpdateDialog` Worker Teardown (`updater_dialog.py`)**: Added `_cleanup_workers()`, `reject()`, and `closeEvent()` to disconnect signals and cleanly detach in-flight `CheckUpdateWorker` / `DownloadUpdateWorker` threads when closing the update dialog early, preventing Qt `QThread: Destroyed while thread is still running` hangs/aborts both in real usage and in diagnostic sweeps.
  - **Forward `UnifiedExportDialog.closeEvent()` to Embedded Plugin Tabs (`export/dialog.py`)**: Added `closeEvent()` on `UnifiedExportDialog` to persist plugin draft state and call `.close()` on embedded plugin pages so `WordPressExportTabWidget.closeEvent()` reliably stops `_yt_thumb_worker` and deletes temporary preview files.
  - **In-App Diagnostic Test Bench & Test #70 Isolation (`diagnostic_dialog.py`, `diagnostics/editor_story_ui_tests.py`, `plugins/wordpress/wp_tab_widget.py`, `plugins/youtube/yt_import_dialog.py`, `cache_manager.py`)**: Scoped `RTVS_TEST_MODE=1` during in-app diagnostic runs, added `_test_project_serialization_round_trip` to `_MAIN_THREAD_TEST_HANDLERS`, respected isolated `settings_store` in `WordPressExportTabWidget` while skipping live HTTP fetches under `RTVS_TEST_MODE`, skipped synchronous `yt-dlp --version` subprocess under `RTVS_TEST_MODE`, added `auto_refresh=False` on `ClearCacheDialog`, passed `auto_start=False` to `CheckUpdateDialog`, and guarded the `scripts.dev_check` AST import for frozen PyInstaller builds.
  - **Plugin Manifest & Bundle Catch-Up**: Synchronized `plugins/wordpress/manifest.json` and `plugins/youtube/manifest.json` (and repackaged `.rtvs-addon` bundles) to `3.10.33-beta`.
